L5

从浏览器到本地服务

L4 学生已经用浏览器 localStorage 复习了。这一课让学生理解「数据应该住在数据库里」+「服务是什么」，并开始写 prompt 让 AI 搭环境。

课前 · 学情起点

学生已经会：

  • L4 用 AI 生成 JSON → 粘贴到页面 → 翻牌复习
  • 三色标记（✓ / △ / ✗）+ localStorage 持久化

学生没经历过：

  • 「换电脑数据丢了」的真实痛点
  • 「服务」这个概念
  • 「数据库」这个概念
  • 写结构化 prompt（四要素）

本章核心命题：数据应该住在独立的地方（数据库）而不是浏览器的抽屉里（localStorage）。怎么搭这件事 —— 让学生写 prompt，AI 干脏活。

⏱️ 90 分钟时间线

5′导入 · 真实场景问题（刷新就丢 / 换电脑就没 / AI 看不到）
15′概念 · 服务是什么
10′概念 · 数据库是什么（和 localStorage 对比）
45′主课 · 写 prompt · 让 AI 帮你搭
10′验证 · AI 做完后如何验证做对了
5′总结 · 对话审计 + 课后预告

📚 详细设计

1. 导入 · 真实场景问题（5′）

老师动作：提一个场景问题，不给答案

  • 「你们 L4 复习的卡片，标记了 ✓ 已掌握 —— 现在让你换个浏览器登录，还能看到吗？」
  • 「想换电脑用呢？」
  • 「想让 AI 帮你看『我哪类卡片总忘记』，AI 能看到吗？」

学生动作：口头回答「不能」「看不到」

💭 设计意图：不抽象讲「为什么 localStorage 不够」，直接抛场景。三个不够 → 升级到「独立的地方」。

⚠️ 撞墙点预案：有学生说「换浏览器也能看到」（说明他用了同步功能 / 同一浏览器）。不要否定，让他演示具体怎么做，然后说「但你让 AI 看到这个数据了吗？」

2. 概念 · 服务是什么（15′）

老师动作：讲一个类比 ——「永远在跑的小店员」

  • 浏览器 = 你（顾客）
  • 服务 = 小店员（永远在店里）
  • 数据库 = 保险箱（店员能打开）
  • 地址 = http://localhost:3000

演示一次「打开地址看页面」 —— 在学生本机或投屏。

学生动作：听 + 看演示

💭 设计意图：「服务」是抽象词。学生不接触代码，但要建立心智模型：服务 = 永远在跑的角色。

⚠️ 撞墙点预案：

  • 学生问「为什么不用网站？」—— 答：「网站也是服务的一种，只是跑在别人电脑上。你这章学的是跑在自己电脑上。」
  • 学生问「服务要钱吗？」—— 答：「本机跑服务不花钱，跑别人电脑才花钱。」

3. 概念 · 数据库是什么（10′）

老师动作：用一张对比表讲 localStorage vs 数据库

  • localStorage：5MB / 锁在浏览器 / AI 进不去 / 慢
  • 数据库：几 GB / 是个文件 / AI 能读 / 快

强调一个关键：数据库对你来说就是一个文件。你不用懂 SQL，让 AI 帮你写查询。

学生动作：对比 localStorage 和数据库，能说出至少 2 个区别

💭 设计意图：学生不接触 SQL，但要建立心智模型：数据库 = 大保险箱 = 文件。

4. 主课 · 写 prompt · 让 AI 帮你搭（45′）

老师动作：演示三件事

  1. 展示一个 prompt 的样子（屏幕上展示 lesson-5.html 里那个示例 prompt）
  2. 拆解四要素（角色 / 任务 / 上下文 / 输出），用表格对照讲解
  3. 抛场景问题，让学生想（不要求写）：「你想让 AI 帮你启动一个本地服务，prompt 里应该包含哪四块？」

然后让学生打开自己的 AI 对话，按场景问题自己写 prompt（不是复制）。

学生动作：

  • 听老师讲四要素
  • 打开 AI 对话，自己写 prompt
  • 让 AI 执行 → 看 AI 输出
  • 如果 AI 没做对，调整 prompt（结构不变，换措辞）

💭 设计意图：这是本节课的核心 —— 学生必须自己写 prompt。复制 = 没学。AI 反馈不对 = 调整 prompt 的能力 = 核心技能。

⚠️ 撞墙点预案：

  • 学生 prompt 极简（只写「帮我搭服务」）→ 引导补「角色」「上下文」
  • AI 执行报错 → 让学生把错误贴给 AI 看，让 AI 自己排查（这是协作能力）
  • 学生电脑没装 Node → 降级：跳过搭建环节，只看概念 + prompt 设计
  • 学生想直接复制示例 → 拒绝：「自己写比复制有用 10 倍」

5. 验证 · AI 做完后如何验证（10′）

老师动作：列出 4 个验证点

  1. 服务在跑 —— 浏览器打开 http://localhost:3000 看到页面
  2. 数据库有内容 —— 让 AI 给你看「数据库里有几条记录」
  3. 浏览器能写 —— 试着标一张卡为「✓」，让 AI 确认数据库里多了这条
  4. 重启不丢 —— 关掉服务再重启，数据还在

学生动作：逐项验证，在 chat 里贴结果让 AI 确认

💭 设计意图：这是和 AI 协作的核心循环 —— AI 做 → 你验证 → 失败告诉 AI → AI 调整。学生必须建立「不轻信 AI 输出」的态度。

6. 总结（5′）

老师动作：发总结 prompt 给 AI

学生动作：口头说明：今天学到的 3 件事

  • localStorage 和数据库的区别（一句话）
  • 服务是什么（一句话）
  • prompt 的四要素是什么

💭 设计意图：不是「学了哪些技能」，是「能用自己的话讲清楚 3 件事」。讲不清楚 = 没懂。

📋 课后自查 · 老师用

✅ 学生达标信号

  • 能用一句话说清「localStorage 和数据库的区别」（说出 1 个以上维度）
  • 能说出「服务」的一个特征（有地址 / 永远在跑）
  • 能拆解任意一个 prompt 的四要素（角色 / 任务 / 上下文 / 输出）
  • 自己写过一个 prompt（不是复制示例）
  • 知道验证 AI 输出的方法（不轻信）

⚠️ 未达标的迹象

  • 把示例 prompt 原封不动复制给 AI
  • AI 报错后不知道把错误贴给 AI
  • 分不清「服务」「数据库」「localStorage」三个概念
  • 认为「AI 做完了 = 对了」（不验证）

🪝 延伸钩子 · 留给 L6

本章结束时，3 个钩子留给 L6：

  1. 数据库里有数据了 —— 但还没用上：L6 可以教「让 AI 读数据库做统计」
  2. 服务只在学生本机：L6+ 可以教云端部署
  3. prompt 四要素学生刚刚学会：L6 用这个能力做更复杂的事（比如让 AI 写周报）
