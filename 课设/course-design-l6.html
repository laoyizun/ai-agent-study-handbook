L6

把数据库搬上云端

L5 学生已经搭好本地数据库。这一课让学生理解"为什么数据要搬到云端"+"云端是什么"+"API key 是什么"，并让 AI 帮他们完成迁移。

课前 · 学情起点

学生已经会：

  • L5 在本机搭好 SQLite，3 张表（students / cards / reviews）
  • 本地数据库里有卡片 + 三色标记
  • prompt 四要素（角色 / 任务 / 上下文 / 输出）
  • 验证 AI 输出（不轻信）

学生没经历过：

  • 「换电脑数据没了」的真实痛点
  • 「云端」这个概念
  • 「API key」这个概念
  • 云端表格编辑器（长得像 Excel）

本章核心命题：数据应该住在一个"任何时候都能打开"的地方。怎么搬 —— 让学生写 prompt，AI 干脏活。学生依然不接触任何代码。

⏱️ 90 分钟时间线

5′导入 · 三个真实场景（换电脑 / AI 看不到 / 别人看不到）
10′概念 · 数据住址的两种选择（本机 vs 云端）
10′概念 · 云端长什么样（网站 + 账号密码 + 表格）
10′概念 · AI 之间的接头暗号（API key）
40′主课 · 写 prompt + AI 搬数据 + 验证
10′验证 · 抽样对比 + 三色标记一致性
5′总结 · 对话审计 + L7 钩子

📚 详细设计

1. 导入 · 三个真实场景（5′）

老师动作：连续提三个场景问题，不给答案

  • 「L5 搭的数据库，你在学校电脑能打开吗？」
  • 「想让 AI 看『我最近哪类错最多』，AI 能看到吗？」
  • 「爸妈问『你家娃最近复习得怎么样』，你给他们看什么？」

学生动作：口头回答「不能」「看不到」

💭 设计意图：不抽象讲"为什么本机不够"，直接抛场景。三个不够 → 升级到"云端"。

⚠️ 撞墙点预案：有学生说"那我用网盘同步本机数据库行不行"——不要否定，让他想一想"网盘同步"和"云端"的区别（一个是文件备份、一个是数据可被 AI 读写）。

2. 概念 · 数据住址的两种选择（10′）

老师动作：讲一个类比 —— "本机保险箱 vs 云端保险箱"

  • 本机 = 你家保险箱 —— 只能你开，换电脑就没
  • 云端 = 银行保险箱 —— 任何分行能开，要有账号密码

强调：换电脑 / AI 看不到 / 别人看不到，三个不够。

老师在投屏时直接用这张图：左边的房子关着门，右边云端开了多个入口。

学生动作：听 + 在自己本机打开 L5 的 SQLite 文件看一眼（确认"它真的在本地"）

💭 设计意图："云端"是抽象词。先建一个具体的心智模型 —— 云端 = 银行保险箱 —— 然后再讲它长什么样。

3. 概念 · 云端长什么样（10′）

老师动作：投屏或截图演示 Supabase 控制台

  • 打开浏览器 → 输网址 → 输账号密码 → 进控制台
  • 左边菜单点 "Table Editor" → 看到一堆表格（长得像 Excel）
  • 点一张表 → 能看到一行一行的数据 → 点一行能改

强调：你依然不写代码。跟 L5 一样，AI 帮你处理。

学生动作：看演示 + 自己在本机打开浏览器试一下（如果老师已经创建了演示账号）

💭 设计意图：学生一旦看到"云端 = 一个能打开的网站 + 像 Excel 的表格"，神秘感就消失了。

4. 概念 · AI 之间的接头暗号 API key（10′）

老师动作：讲类比 —— "俱乐部暗号"

  • AI 帮学生和云端打交道，要报一串字符
  • 这串字符叫 API key，长得像 sb_publishable_xxxxx...
  • publishable = 不是最高机密，但也不能随便发

强调三条规矩：截图打码 / 泄露就重置 / 不写进闪念本。

学生动作：听 + 能在 AI 截图里认出 API key（演示一次）

💭 设计意图：不讲"密钥学"、"认证"、"token"等术语。用"暗号"类比，让学生建立直觉：AI 替你做事也要"亮身份"。

⚠️ 撞墙点预案：

  • 学生问"那我账号密码不也是暗号吗"——答：账号密码是你的暗号，API key 是AI的暗号。
  • 学生问"那是不是所有 AI 都能拿这个 key"——答：理论上能拿到，所以才不能发群里。

5. 主课 · 写 prompt + AI 搬数据（40′）

老师动作：演示三件事

  1. 展示一个 prompt 的样子（屏幕上展示 lesson-6.html 里那个示例 prompt）
  2. 拆解四要素，不重复讲，引用 L5 的拆解（"角色 / 任务 / 上下文 / 输出"已经学过）
  3. 抛场景问题，让学生想（不要求写）：「只想搬 cards 表，prompt 里任务那块怎么写？」

然后让学生打开自己的 AI 对话，按场景问题自己写 prompt（不是复制）。

学生动作：

  • 听老师讲（不重复讲四要素）
  • 打开 AI 对话，自己写 prompt
  • 让 AI 执行 → 看 AI 输出
  • 如果 AI 没做对，调整 prompt（结构不变，换措辞）

💭 设计意图：这是本节课的核心 —— 学生必须自己写 prompt。复制 = 没学。AI 反馈不对 = 调整 prompt 的能力 = 核心技能。

⚠️ 撞墙点预案：

  • 学生 prompt 极简（只写"帮我搬数据"）→ 引导补"角色""上下文""哪些表"
  • AI 执行报错 → 让学生把错误贴给 AI 看，让 AI 自己排查（这是协作能力）
  • 学生误把 API key 发到群里 → 当场演示：让另一个 AI 用这个 key 改一条数据 → 学生看到后果
  • 学生想直接复制示例 → 拒绝："自己写比复制有用 10 倍"

6. 验证 · 抽样对比（10′）

老师动作：列出 5 个验证点（不展开讲，让学生自己点）

  1. 云端网站能看到 3 张表
  2. 字段名跟 L5 定义的一致（特别是 student_name、mark）
  3. 行数对得上
  4. 抽样 3 条卡片看内容是否一致
  5. 三色标记一致性：抽样 ✓ / △ / ✗ 各一条，确认颜色没串

学生动作：逐项验证，在 chat 里贴结果让 AI 确认

💭 设计意图：验证点 5 是本节课最关键的撞墙点 —— 三色标记变了，复习节奏全乱。这是迁移的"质量门"。

7. 总结（5′）

老师动作：发总结 prompt 给 AI

学生动作：口头说明：今天学到的 4 件事

  • 本机和云端的区别（一句话）
  • 云端是什么（一句话）
  • API key 是什么（一句话）
  • 为什么不验证 = 没学

💭 设计意图：不是"学了哪些技能"，是"能用自己的话讲清楚 4 件事"。讲不清楚 = 没懂。

📋 课后自查 · 老师用

✅ 学生达标信号

  • 能用一句话说清"本机和云端的区别"
  • 能说出"云端"对你来说是什么（网站 + 账号密码 + 表格）
  • 能解释"API key"是什么（AI 之间的接头暗号）
  • 知道为什么 API key 不能发到群里
  • 自己写过一个 prompt（不是复制示例）
  • 抽样验证过：云端的卡 + 三色标记和本机一致

⚠️ 未达标的迹象

  • 把示例 prompt 原封不动复制给 AI
  • AI 报错后不知道把错误贴给 AI
  • 分不清"本地""云端""API key"三个概念
  • 认为"AI 搬完了 = 对了"（不验证）
  • 把 API key 发到群里（这条最严重 —— 要单独约谈）

🪝 延伸钩子 · 留给 L7

本章结束时，3 个钩子留给 L7：

  1. 数据上去了但 AI 不会主动用：L7 让 AI 主动读云端数据库，告诉学生"你最近哪类错最多"
  2. 三色标记可以驱动复习节奏：L7 让 AI 根据 ✓△✗ 自动生成"明天该复习哪些卡"
  3. 多端共享还没真用上：L7+ 教"让爸妈登录云端看你的复习情况"

🛠️ 老师参考 · 学生卡上的常见报错

报错原因老师怎么介入
key 无效暗号填错了 / 用过期的让学生回云端网站重新复制一份新的
表已存在之前建过同名表让 AI 帮学生决定"覆盖"或"删旧建新"
