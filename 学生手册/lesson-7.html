让 AI 读回你的卡片

L6 你把数据库搬上了云端。但搬上去 ≠ 用起来 —— 云上的数据，AI 一次都没读过。这一章补上那条箭头：让 AI 自己会去读你攒下的东西，并且只挑你真正薄弱的那几张来问你。

一个真实的问题

周四晚上九点。你在 workbuddy 上说：

「帮我复习受力分析。」

AI 很快给了你一道题 —— 小球沿斜面下滑，求摩擦力。你做了，答案对了。

但你心里清楚 —— 上周那张卡上标的是「未掌握」，卡上写的是：

「画受力图时总漏掉摩擦力方向」

你说「再难一点的」。AI 又给了一道更难的计算题。

它不知道你上周卡在哪。

再看三张卡片

把你自己的卡片库打开，随机抽三张出来看看。你会发现每一张都都对，但每一张都帮不到你：

三张卡片记的都是知识点，而你真正卡的是步骤。

破题

这三张卡片每一张都对，每一张都帮不到你。

原因只有一个：它们记的是知识点，而你卡的是步骤。而且你手上明明有 18 张卡片 —— AI 一张都没读过。

📌 本节 4 步

第 1 步 · 看懂「复习回环」长什么样

AI 帮你复习的时候，这个回环里应该走完 6 个动作。你要能看懂每一个动作在干什么 —— 这一节的重点不是"让 AI 写 prompt"，是你看得懂它在干什么。

第 ② 步和第 ③ 步是这一章的全部 —— 前六章你从没让 AI 做过这件事。

对照着看，你发现了吗？第 ② 步和第 ③ 步以前从来没有发生过。

  • 第 ① 步和第 ④ 步、⑤ 步 —— 你一直在做（问 AI、要题、作答）
  • 第 ⑥ 步写回 —— L4 以后你在网页上手动标，云端才有数据
  • 第 ② 步读回来 —— 一直没有发生。所以 AI 出的题永远跟你的薄弱点无关

第 2 步 · 数据库要加两样东西

要让 AI 知道你"卡在哪一步"、"这次考什么"，数据库得能存这两件事。所以 schema 要加一点东西。

📖 2.1 新的表结构 · 先看要变成什么样

跟 L5 学到的一样：AI 要按固定结构写数据，字段必须先定死。下面是 L7 之后的样子。

变化在哪

多了 1 张表（focus · 存考试重点）、cards 多了 2 列（weakness · 卡在哪一步、focus_id · 这张卡属于哪个重点）。

其他表和字段一个字都没动。你 L5 L6 攒下来的数据全部还在。

-- 第一张 students（没变）
CREATE TABLE students (
  id          BIGSERIAL,
  name        TEXT        NOT NULL UNIQUE,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 第二张 cards（多了 2 列）
CREATE TABLE cards (
  id           BIGSERIAL,
  student_name TEXT        NOT NULL,
  subject      TEXT        NOT NULL,
  question     TEXT        NOT NULL,
  answer       TEXT        NOT NULL,
  weakness     TEXT,        -- 新增：卡在哪一步
  focus_id     INTEGER REFERENCES focus(id) ON DELETE SET NULL,  -- 新增
  created_at   TIMESTAMPTZ DEFAULT now()
);

-- 第三张 reviews（多了 UNIQUE）
CREATE TABLE reviews (
  id          BIGSERIAL,
  card_id     BIGINT      NOT NULL UNIQUE REFERENCES cards(id) ON DELETE CASCADE,
  mark        TEXT        CHECK (mark IN ('done','half','bad')),
  reviewed_at TIMESTAMPTZ DEFAULT now()
);

-- 第四张 focus（全新：你的考试重点）
CREATE TABLE focus (
  id           integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  student_name TEXT    NOT NULL,
  scope        TEXT,    -- 范围，如「物理 一二章」
  topic        TEXT,    -- 具体重点，如「受力分析」
  weight       INTEGER NOT NULL DEFAULT 1,
  created_at   TIMESTAMPTZ DEFAULT now()
);

⚠️ 建表顺序有讲究：focus 必须先建，因为 cards.focus_id 要指向它。

🔒 reviews.card_id 上的 UNIQUE 是唯一约束 —— 一张卡只能有一条复习记录。你改掌握程度是覆盖原来那条，不是追加。少了它，你按三次按钮数据库里就多出三条记录，掌握率统计全乱。

📖 2.2 老数据怎么办 · 两个坑

你 L6 已经往云端搬过数据了。现在加新东西，有两个坑必须知道。

坑 1 · 老卡片没有 weakness，是空的，不是"没有弱点"

你之前那 170 张卡，weakness 这一列全是 NULL（空值）。

NULL ≠ "没有弱点"。NULL 的意思是"还不知道"。如果填成"无"或者空字符串，AI 就没法区分"这卡没弱点"和"这卡我没记录过弱点" —— 前者不用管，后者得让 AI 追问一句。

坑 2 · 同一张卡可能已经有好几条复习记录

如果你之前是用"每次点一下就插一条"的方式标记的，云端可能有同一张卡的多条记录。直接加唯一约束会报错。

处理办法：同一张卡只保留最近的一次（最近的那次才是你现在的真实掌握程度）。这个我们已经在云端处理好了，你的表已经干净。

第 3 步 · 让 AI 读回你的卡片

现在写一段 prompt，让 AI 干这件事。核心就三句：先读、再挑、后写。

📖 3.1 真实可用的 prompt · 复制就能用

先报名字（这是必填字段，不报名字 AI 写不进去）：

第一步 · 报名字（自己打这几个字）：

「我是 your-name，本节课 L7 的学生」

把 your-name 换成你的真实拼音。这一步不能省 —— 少了它，AI 不知道数据该写给谁。

你是我的复习助手。现在请读回我的记忆卡片库，给我做一次真实的复习。

【我的信息】
- 名字：your-name

【云端数据库】
- 地址：https://rwdadlbtvjuoonnbbriy.supabase.co/rest/v1
- 暗号（apikey）：sb_publishable_JgjEFVnjeZPwzn9kO-2qCg_TpE6rIhB

【任务 · 按顺序做，每步做完告诉我结果】

指令 1 · 读我的卡片
  GET /rest/v1/cards?student_name=eq.your-name&select=id,subject,question,answer,weakness
  告诉我：你一共有多少张卡？其中多少张有 weakness（卡点）？

指令 2 · 读我的掌握程度
  GET /rest/v1/reviews?select=card_id,mark
  （**不要加 student_name 过滤**，全拉出来，你自己筛出我 card_id 那几条）
  告诉我：哪些卡标了 bad？哪些标了 half？

指令 3 · 读我的考试重点
  GET /rest/v1/focus?student_name=eq.your-name&select=id,scope,topic,weight
  如果是空的，告诉我"你还没告诉我考试重点"。

指令 4 · 挑出最薄弱的 3 道题
  挑选规则，按优先级：
  a) 先看 focus 里的重点 —— 重点范围内的卡优先
  b) 再看 mark=bad 的卡 —— 完全不会的优先
  c) 然后是 mark=half 的卡
  d) 最后是没标过的卡
  **最多 3 道，最少 1 道**。每道题给我：
     - 问题（不要直接给答案）
     - 这道题在考我 card_id 为几的那张卡
     - 如果那张卡有 weakness，把它写出来（这叫"卡点提示"）
  如果我的卡里有 weakness 是空的，直接说"这张卡没记卡点，只知道知识点是 XXX"。

指令 5 · 等我作答
  我答完之后，你问我：这道题你打 ✓（掌握）还是 △（半掌握）还是 ✗（没掌握）？
  我回答之后，你再往下走。

指令 6 · 把我的标记写回去
  用 **upsert**（不要用普通 insert）：
  POST /rest/v1/reviews?on_conflict=card_id
  Header: Prefer: resolution=merge-duplicates
  Body: {"card_id": 几, "mark": "done 或 half 或 bad"}
  （on_conflict=card_id 一定要放在 URL 参数上，不是 body 里。
    因为 reviews.card_id 上有唯一约束，upsert 才是"覆盖"，insert 会报 409。）

指令 7 · 核对
  全部写完后，核对一遍：
  - GET /rest/v1/reviews?select=card_id,mark
  - GET /rest/v1/cards?select=id,subject,question
  - 按 id 对上号，给我一张表：每张卡的问题 / 这次打的标记 / 写回成功没有

【硬要求】
  - student_name 必须等于「我的信息」里的拼音，一个字都不能错
  - 不要碰 student_name 不是我的记录
  - 改 / 删任何记录前，先告诉我要改哪一条、等我确认
  - 指令 4 最多出 3 道题，**不要一口气出 20 道**
  - 指令 6 必须用 upsert，用 insert 会报错

【出错怎么办】
  任何一步报错，把错误原文贴给我，别自己猜着改。
  常见情况：
  - 404 / PGRST205 → 表结构对不上，告诉我，我检查
  - duplicate key value violates unique constraint → 改用 upsert（第 6 步）
  - 401 / key 无效 → 暗号填错了，告诉我，我重新去网站复制

注意：这段 prompt 里第 5 步是停一下等你说 —— AI 出完题要等你答完再写回。不是一口气做完。

第 4 步 · 卡片质量：让 AI 出能打的牌

回到开头那三张卡片。同样的数据库，换个挑法，卡片质量就变了。

四条规则

四条规则，前三条在 prompt 里，第四条在数据库里。

📖 4.1 重点这件事 · AI 永远不会自己知道

你 L4 学卡片的时候，卡片是"从一次对话里抽知识点"抽出来的 —— AI 抽得很全，但它不知道哪块是你快没时间了，哪块老师说明天必考。

这不是 AI 笨，是信息本来就不在它手上。考试重点只有两个地方知道：老师的脑子，和你的脑子。

所以这一步要做的是你主动给。跟 AI 说一句就行：

我下周考物理一二章，重点是受力分析和浮力。
帮我记下来，以后出题优先从这两块里挑。

然后让 AI 把它写进 focus 表：

POST /rest/v1/focus
Body: {"student_name": "your-name", "scope": "物理 一二章", "topic": "受力分析", "weight": 3}
（weight 是优先级，1 最低。写重点一般给 3，普通内容给 1。）
这一点很重要

你在场景 01 学过「AI 是什么 / 我是谁 / 怎么协作」。这里是第三件事的现实场景：有些信息 AI 永远不会自己知道，你得主动给。

这不是"AI 不够聪明"，这是协作。你把判断权留在自己手里，让 AI 干它擅长的活（出题、归纳、找卡点）。

📖 4.2 老卡片补卡点 · AI 出建议，你来填

你的 170 张卡，weakness 大多是空的。补卡点这件事，AI 只能帮你"想"，不能帮你"定"。

为什么不让 AI 直接写进数据库？回到 L5 学的那条边界 —— AI 可以动手，但你得在旁边看着。卡点写错了，AI 下次就拿着这个错卡点去出题，出的题跟你真正卡的地方没关系，越错越偏。

第一步 · 让 AI 出建议

帮我给 weakness 还是空的卡片补卡点。

规则：
1. 一次只处理 5 张，从最久没复习的开始
2. 卡点必须指向一个**具体的动作或判断**，不能是"不理解""不熟"这种空话
   ✗ "对摩擦力理解不够深"
   ✓ "画受力图时总把重力沿斜面的分量当成摩擦力"
3. 如果你看不出来，就**跳过这张**，在最后告诉我"这 5 张里有几张我看不出来"
4. **只给我建议，不要写进数据库。** 用这个格式列给我：

   卡片 id | 原来的卡点 | 建议的卡点

5. 每条建议后面标一个标记：
   [确定] 我很确定这就是我的问题
   [待定] 看着像，但我不太确定

等我确认哪些要写，我再告诉你写哪几条。

第二步 · 你自己在页面上填

拿到建议之后，打开记忆卡片库页面：

  1. 在顶部「✏️ 我是谁」里选你自己的名字（不选的话卡片上不会出现编辑按钮）
  2. 找到那张卡，点「✏️ 编辑」
  3. 把 AI 建议的卡点填进「卡点 weakness」那一栏
  4. 点「保存」
为什么要多这一步

因为 [确定] 和 [待定] 只有你能分。AI 只能看到卡片的文字，看不到你做题时的表情。

你顺手把 AI 标成「待定」的那些改掉或删掉，你的卡库就干净了。这比事后发现"AI 给我写的卡点全是错的"省事得多。

为什么强调"看不出来就跳过"？因为编出来的卡点比没有卡点更糟 —— AI 会拿着假卡点去出题，出的题跟你真正卡的地方没关系。

第 5 步 · 改和删 · 你的卡片你做主

卡片库不是只读的。你自己加的卡，AI 生成的卡，都可以改、可以删。

页面在哪

记忆卡片库页面：admin/cards.html

它是全班的卡片库 —— 你能看到所有人的卡（这也是 L6 搬上云端的意义）。但改和删只对自己开放，方法是在页面顶部选「我是谁」。

改和删都在页面上做，不用求 AI 代劳。

📖 5.1 什么时候该改，什么时候该删

卡片多了以后，你会遇到两种"这张卡不太对"：

情况怎么办为什么
问题写得太笼统 改 内容没错，但帮不到你。改的时候把问题改具体
答案写错了 改 错的答案比没答案更糟
卡点空着 改 填上你真正卡的那一步
跟别的卡重复了 删 同一件事记两遍，复习时就是浪费时间
当时就没搞懂，留着也没用 删 等你真的搞懂了再重新加一张，比留个半懂的强

👉 打开记忆卡片库页面，选自己的名字，卡片上就有按钮了。

📖 5.2 也能让 AI 帮你改或删

页面上的按钮是给你精细操作用的。但有时候你要动的是"一批" —— 比如某次对话生成的 8 张卡里有 3 张是重复的。这时候让 AI 来做更快：

帮我在卡片库里做两件事，做之前先列清单给我看，我确认了再动手。

【任务 1 · 找重复】
  GET /rest/v1/cards?student_name=eq.your-name&select=id,subject,question,answer
  找出 question 意思重复的卡（意思一样但问法不同也算重复）
  列给我：哪几张重复，重复在哪

【任务 2 · 删除（等我确认）】
  DELETE /rest/v1/cards?id=eq.几
  - 只删我 student_name 名下的
  - **删之前把要删的清单给我看，我点头了再删**
  - 删完告诉我删了几张

【如果我说了要改某张卡】
  PATCH /rest/v1/cards?id=eq.几
  Body: {"weakness": "新的卡点"}
  改之前先把要改的字段和内容给我看

【硬要求】
  - student_name 必须是 your-name
  - 任何 DELETE 之前必须等我确认
  - 不许碰 student_name 不是我的记录
两种做法怎么选

改一张、删一张 → 用页面上的按钮。你亲眼看着改，最快。

找重复、清一批 → 让 AI 做。它能一口气看完几十张卡的文字来找重复，这是人眼干不了的活。但删之前要它把清单列出来给你看。

这就是分工：动手用页面，判断用 AI，删除前一定要人点头。

✅ 完成检查

  • AI 读回了你的卡片 —— 它能说出你有多少张卡、哪些标了 bad
  • AI 出的题不超过 3 道 —— 而且是按「重点 → bad → half」挑的
  • 题目带着卡点提示 —— 你能看出它在考你哪一步
  • 你答完，AI 把标记写回去了 —— 用 upsert 写的，不是 insert
  • 你能核对 —— AI 给的那张对照表，每行的卡和标记都对得上
  • 你告诉了 AI 考试重点 —— focus 表里有记录了
  • 你在页面上改过或删过一张卡 —— 选中「我是谁」后，卡片上出现编辑和删除按钮
  • 你至少抽查过一条 AI 给的卡点建议 —— 把「待定」的那些改掉或删掉

【出错怎么办】
报错就把原文贴给我。常见：
- duplicate key value violates unique constraint → 改用 upsert
- 401 → 暗号填错了
- PGRST205 → 表结构对不上

改完直接发给 AI 就行。它会一步步做，每步停下来告诉你结果。

🔧 撞墙了怎么办

⚠️ AI 出重复的题 / 出的题跟你卡的地方无关

原因：AI 没读到你的卡，或者读错了。

怎么办：让 AI 先回显它读到了什么：

先别出题。先把你刚才读到的 cards 和 reviews 完整贴给我看，
每张卡一行：card_id | 问题 | weakness | mark。
我要先确认你读对了，再让你出题。

如果 AI 贴出来的卡根本不是你的，多半是 student_name 打错了。

⚠️ 写回去报 duplicate key value violates unique constraint

原因：AI 用了普通 insert，但这张卡已经有记录了。

怎么办：让它改成 upsert，并且强调参数位置：

改用 upsert：
POST /rest/v1/reviews?on_conflict=card_id     ← on_conflict 放 URL 参数上
Header: Prefer: resolution=merge-duplicates
Body: {"card_id": 几, "mark": "done"}

不要放在 body 里，body 里放 on_conflict 会报 PGRST204。
⚠️ AI 不肯写 / 说"我无法访问你的数据库"

原因：它把"读取网页"和"发 HTTP 请求"搞混了。你要明确说：

你不是要"看网页"，是要**发 HTTP 请求**。
用 curl 就行：
curl -s "https://rwdadlbtvjuoonnbbriy.supabase.co/rest/v1/cards?select=id&limit=5" \
  -H "apikey: sb_publishable_JgjEFVnjeZPwzn9kO-2qCg_TpE6rIhB" \
  -H "Authorization: Bearer sb_publishable_JgjEFVnjeZPwzn9kO-2qCg_TpE6rIhB"

先跑这一条，把返回结果贴给我。
⚠️ AI 写的题你一道都不会 / 一道都太简单

原因：卡片的 weakness 是空的，或者重点没告诉它。

怎么办：两件事——先补卡点，再补重点：

我们先做两件事，出了题再来：

1. 给我 5 张 weakness 是空的卡，你帮我补卡点（规则见下）
2. 我告诉你这次考什么，你记进 focus 表

然后再出题。

补卡点的规则：卡点必须指向一个具体的动作或判断，不能是"理解不够深"这种空话。看不出来就跳过，别硬编。

🪝 留给 L8：

  • 你的卡片按知识点长出来了（哪些卡属于同一块、哪块最薄弱）
  • 同班同学也在同一个知识点上栽跟头 —— 但要不泄露名字地看到
  • 你的复习记录只有你自己看 —— 这需要数据库层面加权限（RLS），不是网页上藏一藏就行的
