5

从浏览器到本地服务

L4 把复习记录存在浏览器里。这一章让你理解「为什么数据应该住在数据库里」，以及怎么让 AI 帮你搭起来。

一个真实的问题

你在 L4 复习卡片，标记「✓ 已掌握」。刷新页面，状态还在。

但是 ——

  • 你换个浏览器登录，状态没了
  • 你换台电脑用，状态没了
  • 你让 AI 帮你看「我上周复习过什么」，AI 说「我不知道」

为什么会这样？因为 L4 的数据存在 浏览器的 localStorage 里 —— 浏览器关掉就锁在自己家，AI 进不去。

这一章要解决的就是：数据应该住在一个独立的地方。这个地方叫「数据库」。访问数据库的那个角色叫「服务」。

📌 工作流（4 步）

1

场景 · 复习数据为什么留不住

三个不够 —— 不只是「理论上的问题」，是你 L4 上完后一定会撞到的具体场景。

📖 三个真实场景 · 你会撞到哪个

场景 1：换电脑 / 换浏览器 = 数据归零

L4 的数据存在 localStorage 里 —— 这是浏览器给每个网站分配的「小抽屉」。换浏览器、换电脑、清理浏览器数据，抽屉就没了。

场景 2：AI 进不去你的复习历史

你想让 AI 帮你分析「我哪类卡片总忘记」，AI 看不到你 localStorage 里的数据。AI 只能读文件，读不到浏览器的抽屉。

场景 3：一学期下来数据爆掉

localStorage 限额大约 5MB。听起来很大，但你加上「每次复习的时间戳」「每次的标记」「你自己的批注」，一学期下来可能到 4MB。再往下就报错。

三个场景共同指向一个解法：数据搬到独立的地方。

2

概念 · 服务是什么

服务 = 一个永远在跑的小店员。你走开它还在电脑里值班，浏览器给它发请求，它接得住。

📖 服务是什么 · 怎么验证它在跑

数据不能浏览器直接改。必须经过中间这个"永远在跑"的服务。

类比 · 永远在跑的小店员

你可以这样想：

  • 浏览器 = 你（顾客）
  • 服务 = 小店员（永远在店里）
  • 数据库 = 保险箱（店员能打开）
  • 你发请求 = 你对小店员说「把这条复习记录存保险箱」
  • 店员存好 = 数据库里多了一条记录

服务的两个特征：

  • 有地址 —— 通常是 http://localhost:3000，浏览器通过这个地址找到它
  • 永远在跑 —— 你关掉浏览器它不关，除非电脑关机或你主动停止

怎么知道服务在跑？

浏览器打开 http://localhost:3000，如果看到任何页面（哪怕是「服务运行中」一行字），说明服务在跑。看到「无法连接」说明服务没起。

3

概念 · 数据库是什么

数据库 = 一个比 localStorage 大得多的保险箱。可以存几万条记录，AI 也能读它。

📖 数据库 vs localStorage · 关键区别

localStorage 的局限：

  • 存 5MB 上限
  • 只在浏览器里，换电脑就丢
  • AI 进不去
  • 查询慢（要在所有数据里翻）

数据库的优势：

  • 能存几 GB 甚至更多
  • 是一个文件，可以拷到任何电脑
  • AI 能直接读（因为它是个文件）
  • 查询快（按索引找）

数据库长什么样？

对你来说，数据库就是一个文件 —— 比如 memory-cards.db。你不用关心里面怎么存，你只需要知道：

  • 它在硬盘上
  • 服务能打开它
  • AI 能读它
  • 它和 localStorage 的本质区别是「独立于浏览器」

你不需要懂 SQL。你只需要知道：让 AI 帮你写「存一条」「读一条」「统计一下」的请求就行。

4

写 prompt · 让 AI 帮你搭起来

整个升级过程不是你去敲命令、写代码，而是你写 prompt，AI 干脏活。但你得理解概念才能写出好的 prompt。

📖 4.1 看一个 prompt 是什么样

这是「让 AI 帮你检查 Node.js 是否安装」的一个 prompt 示例（仅展示，不要复制）：

你是我的电脑环境检查助手，不是通用聊天 AI。

【角色】你懂 Node.js 安装和命令行
【任务】帮我检查电脑是否安装了 Node.js
【上下文】我是初中生，对命令行不熟，需要你一步步带我
【输出要求】先告诉我检查思路，再告诉我具体敲哪条命令，最后把命令输出贴回来让我看

这是「展示」，不是「模板」。看一遍就行，下一段拆解它的结构。

📖 4.2 拆解 prompt · 四要素结构

一个能用的 prompt 通常有四块。少一块 AI 就会跑偏。

要素 是什么 示例里是哪一句
角色告诉 AI 它是谁「你是我的电脑环境检查助手，不是通用聊天 AI」
任务要 AI 做什么「帮我检查电脑是否安装了 Node.js」
上下文你的背景 / 限制「我是初中生，对命令行不熟，需要你一步步带我」
输出AI 该怎么给结果「先告诉我思路，再告诉我具体命令，最后贴回输出」

为什么四要素都要有？

  • 少「角色」：AI 不知道自己该用什么口吻，可能给你讲一堆无关的
  • 少「任务」：AI 不知道做什么，会泛泛而谈
  • 少「上下文」：AI 默认你是工程师，给的命令你敲不动
  • 少「输出」：AI 可能直接跑命令不告诉你，导致你看不到过程
📖 4.3 场景思考 · 你自己想写一个 prompt

不需要你现在就写出来。但想一想这个场景：

场景：你想让 AI 帮你启动一个本地服务，让浏览器能读写数据库。

你要发给 AI 的 prompt 里应该包含哪四块？每块大概写什么？

动手之前，先在脑子里过一遍：

  • 角色：AI 是谁？「服务搭建助手」？「本地开发伙伴」？
  • 任务：要 AI 做什么？「帮我搭一个 Node 服务」？
  • 上下文：你的限制是什么？「我用 Node + SQLite」「我在 macOS」
  • 输出：AI 该给什么？「给我能跑的命令」「告诉我服务怎么验证在跑」

下次真要搭的时候，按这个结构自己写一个 prompt —— 别复制，自己写。

📖 4.4 验证 · 怎么知道 AI 做对了

AI 执行完后，你要能验证它做对了。验证点：

  • 服务在跑 —— 浏览器打开 http://localhost:3000 看到页面
  • 数据库有内容 —— 让 AI 给你看「数据库里有几条记录」
  • 浏览器能写 —— L4 页面试着标一张卡为「✓」，让 AI 确认数据库里多了这条
  • 重启不丢 —— 关掉服务再重启，数据还在

任何一步不对，告诉 AI「这一步没成功」，让它排查。AI 会读日志 / 改命令 / 重新跑 —— 这是你和 AI 协作的核心循环。

📖 4.5 你要建的 3 张清单 · 字段定下来

之前 L4 你做卡片时只有「问题 / 答案 / 章节」3 项，够用。但升级到数据库后，AI 要按固定结构写入数据 —— 字段必须一致，否则 AI 写不进去。

⚠️ L5 本地 SQLite 和 L6 云端 Supabase · 字段必须完全一致

下面是 L5 + L6 共用的字段定义。AI 在你本机建 SQLite 时，要按这个 schema 来建；L6 上云端时不会重建表，直接用同一份字段。

完整 schema 参考（你可以直接复制给 AI 让它检查建对了没）：

-- 第一张 students
CREATE TABLE students (
  id          BIGSERIAL,  -- 本地 SQLite 用 INTEGER PRIMARY KEY AUTOINCREMENT
  name        TEXT        NOT NULL UNIQUE,
  created_at  TIMESTAMPTZ DEFAULT now()  -- 本地用 CURRENT_TIMESTAMP
);

-- 第二张 cards
CREATE TABLE cards (
  id           BIGSERIAL,
  student_name TEXT        NOT NULL,
  subject      TEXT        NOT NULL,
  question     TEXT        NOT NULL,
  answer       TEXT        NOT NULL,
  created_at   TIMESTAMPTZ DEFAULT now()
);

-- 第三张 reviews
CREATE TABLE reviews (
  id          BIGSERIAL,
  card_id     BIGINT      NOT NULL,
  mark        TEXT        CHECK (mark IN ('done','half','bad')),
  reviewed_at TIMESTAMPTZ DEFAULT now()
);

⚠️ 注意：BIGSERIAL 是 Supabase 写法；SQLite 用 INTEGER PRIMARY KEY AUTOINCREMENT。TIMESTAMPTZ 是云端，本地用 TEXT DEFAULT CURRENT_TIMESTAMP。字段名必须一致，类型不同没关系。

下面是 3 张清单的字段定义（你和 AI 都会用到）：

3 张表是有"上下级"的：reviews 上面挂着 cards，cards 上面挂着 students。

📋 第一张：谁是你（students）

显示名字段名说明
名字name你的名字（你填）
加入时间created_at系统自动填

📋 第二张：你的卡片（cards）

显示名字段名说明
属于谁student_name你的名字（和第一张关联）
学科subject数学 / 英语 / 物理……
问题question卡片的正面
答案answer卡片的反面
加卡时间created_at系统自动填

📋 第三张：你的复习（reviews）

显示名字段名说明
哪张卡card_id第二张里的编号
标记mark✓ / △ / ✗
复习时间reviewed_at系统自动填
📖 发给 AI 的 prompt（让 AI 帮你建这 3 张清单）

把下面这段话复制给 AI：

请帮我在我的电脑上装一个本地数据库（SQLite），建以下 3 张清单。
建完后告诉我是不是有 3 张清单 + 每张清单的字段是不是和下面一致。

━━━━━━━━━━━━━━━━━━━━━━━━━━
第一张：谁是你（students）
━━━━━━━━━━━━━━━━━━━━━━━━━━
- 名字（name）：填你的名字
- 加入时间（created_at）：系统自动填

━━━━━━━━━━━━━━━━━━━━━━━━━━
第二张：你的卡片（cards）
━━━━━━━━━━━━━━━━━━━━━━━━━━
- 属于谁（student_name）：填你的名字（和第一张关联）
- 学科（subject）：填数学 / 英语等
- 问题（question）：填卡片的正面
- 答案（answer）：填卡片的反面
- 加卡时间（created_at）：系统自动填

━━━━━━━━━━━━━━━━━━━━━━━━━━
第三张：你的复习（reviews）
━━━━━━━━━━━━━━━━━━━━━━━━━━
- 哪张卡（card_id）：填第二张里的编号
- 标记（mark）：填 ✓ / △ / ✗
- 复习时间（reviewed_at）：系统自动填

注意：这是「展示」，不是「模板」。下次真的要让 AI 搭数据库时，自己写 —— 按 4.2 拆的四要素结构来。

📖 验证 · AI 建好后怎么知道建对了

完成后让 AI 告诉你：

  1. 是不是有 3 张清单（students / cards / reviews）
  2. 每张清单的字段是不是和上面表格一致
  3. 能不能看到「name」「student_name」「mark」这些字段

任何一项不对，让 AI 重做。这是你和 AI 协作的核心循环。

为什么字段必须一致？

L6 上云端时也用同样的 3 张清单、同样的字段。你现在定义一次，L6 直接对接，不需要重新填数据。

📖 4.6 把你之前的 md / json 转成表数据 · 直接复制用的 prompt

之前 L3 你写过闪念本 .md、L4 你用过记忆卡片 .json、L4 复习页用过 localStorage。这些数据现在散在不同文件里。L5 要把它们整理成 3 张表的字段，L6 才好一次性搬上云。

为什么不能直接搬？

  • 闪念本.md 里的标题 / 段落 / bullet 不是表字段
  • 记忆卡片.json 里的 front / back 键名跟 cards.question / cards.answer 不一样
  • localStorage 里的 ✓△✗ 存在浏览器里，AI 看不见

所以要让 AI 帮你转换。转换规则已经定好，学生直接复制下面 prompt 给 AI，AI 会自动读你的文件 + 整理成 INSERT 语句。

第一步 · 报名字

在 AI 对话开头打：

我是 your-name，本节课 L5 的学生

your-name 是你名字后两个字的拼音（例如 haolin / xiaoyu / zhengheng / haobin / minjun / mingle）。

第二步 · 复制 prompt 给 AI

你是本班的本地数据整理助手，不是通用聊天 AI。

【角色】你懂 Markdown / JSON / SQLite 三种格式，能帮学生把分散的数据整理成数据库表的 INSERT 语句

【任务】
  1. 读我工作空间里的所有"知识数据"文件
  2. 把内容整理成下面 schema 对应的 INSERT 语句（让我手动复制粘贴到本地 SQLite 跑）
  3. 不要直接改我的任何文件，**只输出 INSERT 语句给我**

【上下文】
  - 我是初中生，姓名（后两个字拼音）：your-name（见开头我告诉你的）
  - 我的数据散在 3 个来源里：
    a) 闪念本 .md 文件（路径通常是 ~/我的工作空间/闪念本/ 或类似位置）
    b) 记忆卡片 .json 文件（路径类似 ~/我的工作空间/记忆卡片/）
    c) localStorage（我在 L4 复习页浏览器里存的 ✓△✗ 标记 —— 这部分我需要你告诉我怎么导出成 JSON）
  - 目标 schema（**字段名必须严格一致**）：

━━━━━━━━━━━━━━━━━━━━━━━━━━
students 表
━━━━━━━━━━━━━━━━━━━━━━━━━━
INSERT INTO students (name) VALUES ('your-name');

━━━━━━━━━━━━━━━━━━━━━━━━━━
cards 表（每张闪念本条目 / 每张记忆卡片 = 一行）
━━━━━━━━━━━━━━━━━━━━━━━━━━
INSERT INTO cards (student_name, subject, question, answer) VALUES
  ('your-name', '数学', '勾股定理的几何意义', 'a²+b²=c² 表示直角三角形两直角边平方和等于斜边平方'),
  ('your-name', '数学', '...', '...'),
  ...;

━━━━━━━━━━━━━━━━━━━━━━━━━━
reviews 表（每条 ✓△✗ = 一行）
━━━━━━━━━━━━━━━━━━━━━━━━━━
INSERT INTO reviews (card_id, mark) VALUES
  (1, 'done'),   -- ✓ 已掌握
  (2, 'half'),   -- △ 半掌握
  (3, 'bad');    -- ✗ 未掌握

━━━━━━━━━━━━━━━━━━━━━━━━━━

【转换规则 · 必须遵守】
  - cards 表的 student_name 全部填你自己的拼音，不要写别人
  - 闪念本 .md 里"AI 给的好解释"每一条 bullet = cards 表一行（question 用 bullet 标题，answer 用 bullet 内容）
  - 记忆卡片 .json 的 front → cards.question，back → cards.answer，mark → reviews.mark
  - localStorage 里的 mark 字段：✓ = 'done'，△ = 'half'，✗ = 'bad'
  - card_id 是 cards 插入后 AI 给我返回的 id 列表，要按那个顺序插 reviews
  - 如果某条数据你看不懂、字段对不上，**停下来告诉我不要自己猜**

【输出要求】
  - 第一步：列出你找到的所有文件路径 + 每个文件有几条数据
  - 第二步：告诉我 localStorage 数据怎么导出（具体步骤、点哪个按钮）
  - 第三步：等我确认后，输出完整的 INSERT 语句（按上面的 schema）
  - 任何一步报错，把错误原文贴回来

【验证】
  - INSERT 语句生成后，你自己用 SQLite 跑一遍（在你的环境里跑，**不要动我本机文件**），跑通了告诉我每张表有几行
  - 我再自己用 sqlite3 命令行跑一次，最终以我跑出来的为准

第三步 · 拿到 INSERT 语句后，自己跑

AI 会给你一段 INSERT 语句，你复制到终端跑（不是直接让 AI 跑）：

# 在你电脑的 SQLite 数据库文件路径下（先问 AI 这个文件在哪）
sqlite3 ~/你的路径/memory-cards.db < generated_inserts.sql

# 跑完后看一下结果
sqlite3 ~/你的路径/memory-cards.db "SELECT COUNT(*) FROM students; SELECT COUNT(*) FROM cards; SELECT COUNT(*) FROM reviews;"

注意：这是 真实可用的 prompt，不是示例。把 your-name 换成你自己的拼音就能用。改的过程你会注意到"为什么要写这些字段"。

做完 L5 这一步 → L6 就简单了：本地 SQLite 已经有数据，且字段和云端一致。L6 上云时 AI 只需要读本地 SQLite → HTTP 请求发给云端，不用再转格式。
